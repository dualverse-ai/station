# Construction Survey

This note is a compact scientific survey of the construction languages bundled
with `epoch_book_b`.  The emphasis is on source laws that generate witnesses,
not on saved adjacency strings.

## Generator Hierarchy

Use the most structural construction available for a value of `n`:

1. **Two-copy Paley.**  For `q = 2n - 1`, with `q = 1 mod 4` a prime power,
   use two field layers and the quadratic-residue/nonresidue split.  This gives
   a uniform finite-field family.
2. **S/K one-relation conference construction.**  For `q = n - 1`, a
   conference relation with parameters
   `(q, (q-1)/2, (q-5)/4, (q-1)/4)` feeds a fixed four-chamber plus
   two-endpoint rule table.  Paley conference relations give many rows, and the
   included non-prime-power conference masks for `q=45` and `q=65` extend the
   family beyond prime powers.
3. **Skew-Paley sum kernel.**  For `q = 4n - 1`, with `q = 3 mod 8` a prime
   power, a one-copy graph on `GF(q)^*` uses the quadratic character of `x+y`.
   The exact certificate is a Seidel row-correlation identity.
4. **Algorithmic finite bicirculant searches.**  For remaining finite rows,
   work on two cyclic fibers of size `m=2n-1`.  The active baseline uses a
   deterministic Tenax Tabu search for `n=22,23,24,28,29,32,34`, a
   capacity-profile language for `n=36`, a `Z_7 x Z_11` product completion for
   `n=39`, and a `Z_85` orbit deconvolution for `n=43`.
5. **Historical bridge/complementary ledgers.**  These are useful background
   for understanding low-row search structure, but the active baseline no
   longer loads bridge source-law rows as certificate input.

The baseline builder follows this hierarchy by trying S/K, two-copy Paley,
skew-Paley, and then the executable finite generators.

## Unified Finite Search Grammar

The most useful finite search language is the two-fiber bicirculant one:

```text
m = 2n - 1
V = {0,1} x Z_m
S_U  subset Z_m^*, often inverse-symmetric
S_V  subset Z_m^*, often inverse-symmetric
S_UV subset Z_m, directed cross relation
```

Edges are emitted by cyclic differences.  In bridge-normal form one may impose
`C = Z_m^* \ A` and reduce the problem to residual inequalities such as:

```text
N_A(d) + N_B(d) <= n-2          if d in A
N_A(d) + N_B(d) <= 2|A|-n+1     if d notin A
```

The active finite baseline is implemented in
`epoch_book_b_finite_generators.py` and its companion C/Python generators:

- `epoch_book_b_tenax_tabu.c` searches two same-fiber residue arrays and a
  directed cross array for `n=22,23,24,28,29,32,34`.
- `epoch_book_b_n36_c_search.c` implements the long capacity-profile search
  behind the preloaded `n=36` source row.
- `epoch_book_b_n39_phase1.c` and
  `epoch_book_b_n39_phase2_template.c` run the product-group search and
  generated fixed-`A` completion for `n=39`.
- `epoch_book_b_n43_orbit.py` exhausts multiplication-by-4 orbit choices in
  `Z_85` for `n=43`.

The reference file `finite_search_algorithms.py` includes:

- residual-row evaluation;
- a transparent simulated-annealing loop for the complementary bicirculant
  objective;
- fixed-`A` CP-SAT completion when OR-Tools is available;
- bridge source-law residual checks.

These routines are intentionally small and readable.  They are meant to expose
the successful search grammar so it can be improved, generalized, or replaced
by a theorem.

## Extension Guidance

- First check whether a target falls into two-copy Paley, S/K, or skew-Paley.
- If not, work in the bridge bicirculant residual equations rather than raw
  adjacency space.
- For composite `m`, inspect CRT row profiles, but require componentwise
  residual rows `<= 0`; scalar ledgers alone are not enough.
- If a finite hit is found, report the source law or search grammar that emits
  it, then validate by exact book caps.
