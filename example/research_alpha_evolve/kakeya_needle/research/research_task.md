## Research Task: Kakeya Needle Triangle Area Optimization

**This specification holds the highest degree of credibility in this research station and overrides all other sources.**

### 1. Problem Description

For each tested integer `n`, construct real offsets `x_1, ..., x_n`. These offsets define `n` thin triangles:

```
T_j = conv((x_j, 0), (x_j + 1/n, 0), (x_j + j/n, 1)),  j = 1,...,n.
```

The goal is to make the area of the union

```
|T_1 union T_2 union ... union T_n|
```

as small as possible.

This is a constructive finite model of the 2D Kakeya needle problem. The central goal is not merely to optimize the listed benchmark values of `n`, but to discover a coherent construction principle that defines offsets for arbitrary `n`.

The official evaluator uses a finite calibration set. A high-quality submission should therefore provide a deterministic general algorithm `positions(n)` and then instantiate it on the tested values. Pure lookup tables or per-`n` hand-tuned offsets may score well, but they are mathematically secondary unless they reveal a transferable construction mechanism.

### 2. Evaluation Overview

The evaluator tests exactly:

```
n = 2, 3, 4, 5, 8, 9, 16, 17, 32, 33, 64, 65, 128, 129
```

For each tested `n`, it:

- reads the submitted list of `n` real offsets,
- builds the triangles `T_j`,
- computes the triangle-union area by deterministic vertical sweep,
- computes the Keich-style baseline area for the same `n`, and
- forms the ratio `submitted_area / keich_area`.

The primary score is the geometric mean of these ratios across all tested `n`.

Lower scores are better.

### 3. Task Constraints and Goals

- **Primary score:** geometric mean of relative area ratios across all tested `n`, lower is better.
- **Target:** find a deterministic general construction `positions(n)` for every integer `n >= 2` whose finite calibration score is at most `0.90`.
- **Finite calibration:** the official evaluator cannot test every `n`; it tests powers of two and the neighboring values `2^k + 1` through `129`. Passing the official target is evidence for the general goal, not a proof of it.
- **Tested values:** `2, 3, 4, 5, 8, 9, 16, 17, 32, 33, 64, 65, 128, 129`.
- **Offsets:** finite real numbers. They do not need to be positive; translating all offsets for a fixed `n` does not change the area.
- **Execution Timeout:** 15 minutes (900 seconds).
- **Resource Limits:** Each official submission is allotted one GPU when GPU resources are available. Standard Python libraries, NumPy, and GPU-capable JAX are available.

### 4. Submission Format

- The submitted Python file **must** define:

```python
def construct_kakeya() -> str:
    """
    Return Kakeya triangle offsets generated by one deterministic general rule.
    """
    def positions(n: int) -> list[float]:
        # Replace this seed with a construction intended to work for arbitrary n.
        return [0.0] * n

    tested = [2, 3, 4, 5, 8, 9, 16, 17, 32, 33, 64, 65, 128, 129]
    payload = {n: positions(n) for n in tested}
```

- The returned string must be a Python literal dictionary.
- Dictionary keys may be integers or strings, for example `16` or `"16"`.
- Every tested `n` must be present.
- Each value must be a one-dimensional list of exactly `n` finite real numbers.
- The evaluator only receives offsets for the tested values, but the research goal is a general construction. If your code uses a dictionary of unrelated per-`n` constants, explain why those constants arise from a broader rule. Otherwise, treat the result as a finite benchmark optimization rather than a mathematical construction.
- Invalid submissions are reported as `n.a.`.
- **Evaluator implementation:** the definitive checks live in the evaluator source.

### 5. Scoring

For valid submissions, define:

```
ratio_n = area(submission, n) / area(Keich-style baseline, n)
score = geometric_mean(ratio_n over tested n)
```

Lower scores rank higher in the Research Center. However, ranking is not the only measure of success: a slightly worse score from a clear general construction may be more valuable than a better score from unrelated finite optimizations.

The Keich-style baseline has score exactly `1.0`. The official calibration target is reached when:

```
score <= 0.90
```

### 6. Keich-Style Baseline

For every tested `n`, the baseline uses the following bitwise construction:

```python
def keich_positions(n):
    k = ceil(log2(n))
    xs = []
    for i in range(n):
        eps = first_k_binary_digits_of_fraction(i / n)
        xs.append(sum((1 - j) * eps[j - 1] * 2**(-j) / k for j in range(1, k + 1)))
    return xs
```

For powers of two this agrees with the usual Keich bitwise construction. For `2^k + 1` calibration values it is the natural binary-fraction extension used to measure post-power behavior. The evaluator computes the baseline internally.

### 7. Mathematical Exploration Goals

The official score is a calibration benchmark, not the sole research objective. For this task, mathematicians would especially value:

- a simple deterministic algorithm `positions(n)` that is meaningful for every `n >= 2`;
- evidence that the construction behaves well on non-powers of two, especially near `n = 2^k + 1` where naive Keich-style extensions can jump;
- a construction with asymptotic analysis or a plausible bound for large `n`;
- a proof or convincing derivation of the area of a proposed family, even if only for powers of two or for a restricted class;
- structural explanations for why a construction improves on Keich, such as bit/valuation laws, recursive even-odd decompositions, overlap identities, or symmetry-breaking mechanisms;
- finite optimized examples that expose a reusable pattern rather than isolated coordinates;
- negative results that rule out natural construction families or identify barriers to generalization.

If you discover a transferable construction principle, asymptotic estimate, exact formula, or structural obstruction, publish the mathematical details in the Archive Room even if the official score does not improve.

### 8. Secondary Metrics

The evaluator reports:

- `RelativeArea`: the primary score, equal to the geometric mean of `ratio_n`
- `TargetMargin`: `RelativeArea - 0.90`
- `GeometricMeanRatio`: same value as `RelativeArea`
- `MeanRatio`: arithmetic mean of `ratio_n`
- `BestRatio`: smallest `ratio_n`
- `WorstN`: tested `n` with the largest `ratio_n`
- `BestN`: tested `n` where `BestRatio` occurs
- `ValidCount`: number of tested `n` values parsed and evaluated successfully

The result message also includes the worst tested ratio and the per-`n` ratios for the finite calibration set.
